# Taste Learnings
- Always read project-level instruction/context files (e.g., `.ai/` folder, project docs, spec files) before analyzing code or making claims about project state. The user expects thorough context-gathering up front, not jumping to conclusions from surface-level code inspection. Confidence: 0.85
- When the user asks to "run it" or wants a deliverable, actually attempt execution — don't just write scripts and explain how to run them. The user expects the agent to produce concrete results (e.g., a built installer in a specific folder), not instructions. Confidence: 0.8
- When missing tools or dependencies block a task, proactively install them (e.g., via winget, pip, aqtinstall) rather than reporting the absence and asking the user to handle it. The user expects self-sufficient problem-solving. Confidence: 0.85
- When the AI loses focus or makes mistakes, the user sends minimal signals (e.g., just "retry") and expects the AI to self-correct without elaboration. Don't require verbose re-explanation. Confidence: 0.8
- Provides exhaustive specifications with every detail spelled out — exact default values, option labels, and layout expectations — all in one message. When re-iterating goals, includes the full specification again rather than referencing previous messages. Confidence: 0.85
- Uses screenshots alongside text to show current UI state and bugs visually. Expects the AI to analyze the visual evidence and fix accordingly. Confidence: 0.85
- Strongly prefers concise, actionable communication — short messages like "retry" rather than lengthy explanations of what went wrong. Confidence: 0.8
- Prefers minimal UI with no hand-holding features — removes welcome screens, first-launch popups, and similar onboarding elements. Wants a clean interface without unnecessary prompts. Confidence: 0.7
- Aggressively strips features considered unnecessary from applications — update notifications, recent files tracking, and similar "convenience" features should be fully removed from both code and UI, not just disabled. Confidence: 0.85
- Expects OS-native behaviors to be replicated — sorting should follow Windows Explorer conventions, thumbnail generation should match Explorer's supported formats. Confidence: 0.8
- Expects SVG and vector images to display at their default/native size, not stretched to fill the viewport or maximized. Images should never upscale beyond 100% of their actual pixel dimensions — the display should respect native image sizes. Confidence: 0.8
- Carefully selects UI label wording and cares about specific term choices (e.g., "Middle" vs "Center"). Labels should be reviewed and chosen deliberately. Confidence: 0.75
- Expects all keyboard shortcuts to be discoverable through the Settings UI — custom shortcuts must appear in the shortcuts list alongside standard ones. Confidence: 0.8
- Expects behavior changes to be stateful and reversible — e.g., "toggle original size" should remember and restore the previous zoom level, not just snap to a preset. The saved "previous" state must be live-updated whenever the user changes zoom, so restoring always returns to the most recent user-adjusted state, not just the state at the moment of the first toggle. Viewport scroll position should also be saved and restored as part of the state, not just zoom level. Confidence: 0.85
